# 角色 Prompt 与 SoulMD 质量规范（v4）

本规范适用于 `data/characters.json` 中所有可聊天角色。旅行者元素变体不属于聊天角色，不生成角色 Prompt。

## 数据目标

每个角色必须同时具备两层资料：

1. `prompt`：角色专属私聊行为提示词，不少于 1000 个字符。它决定角色如何理解自己、旅行者、当前时间线和微信聊天节奏。
2. `groupPrompt`：面向群聊导演的紧凑角色资料。上游导入角色不少于 700 个字符，并由运行时按群成员数量限制总预算。
3. `soulMd`：角色事实档案。DGP 上游导入角色必须完整保留对应 `SKILL.md` 正文；本地自建角色不少于 2000 个字符。

两层内容必须针对角色单独撰写。允许共享少量安全约束，但禁止只替换姓名、地区和元素的模板化生成。

## Prompt 必备结构

- `【最高优先级身份】`：明确角色不是 AI、助手或程序；明确“用户就是旅行者”。
- `【人物本质】`：身份、性格矛盾、生活重心、喜好、厌恶和行为边界。
- `【经历与当前剧情】`：按时间顺序概述关键经历，并更新到资料截止时最新可核实剧情。
- `【与旅行者】`：写清相识、共同事件、当前信任程度和未完成事项。
- `【确认的人物关系】`：仅记录有来源支持的相识者，区分亲友、同僚、敌人、听闻和历史人物。
- `【未知关系边界】`：未列人物不得凭空成为旧识；群聊首次出现时按陌生人或仅听闻处理。
- `【语言与聊天方式】`：具体描述普通微信聊天中的句长、节奏、口头习惯、情绪变化与禁用风格。
- `【原作语气锚点】`：至少 5 条短小的原作台词或严格忠实的短句摘录，只用于模仿，不机械复读。
- `【聊天示例】`：本地自建 Prompt 至少包含 5 组。DGP 上游导入角色以其完整“表达 DNA”“关键引用”和角色扮演规则为准，不为凑数量伪造原作示例。

## SoulMD 必备结构

本地自建 SoulMD 使用以下结构：

- `# <角色名> SoulMD`
- `## 核心身份`
- `## 性格与内在矛盾`
- `## 生平与关键经历`
- `## 当前时间线`
- `## 与旅行者的关系`
- `## 人物关系网`
- `## 能力、职责与生活`
- `## 知识与关系边界`
- `## 资料来源`

DGP 上游导入 SoulMD 则必须完整保留原文件正文、固定提交来源和以下上游章节：角色扮演规则、身份卡、核心心智模型、表达 DNA、人物时间线、诚实边界、关系图谱和关键引用。

## 上游导入

- 上游正文固定在 `third_party/Genshin.Skill/skills/`，不得只保存远程链接。
- `MANIFEST.json` 必须记录应用角色 ID、原文件路径和 SHA-256。
- `promptProvenance` 必须记录项目、提交、路径、许可与适配方式。
- `npm run import:dgp-skills` 的结果必须可重复；连续执行不应产生无意义差异。
- 使用 `npm run audit:dgp-import` 检查 97 份上游文件、角色映射、正文完整性与聊天适配。

## 事实与来源

- 优先使用米哈游/HoYoverse 官方角色介绍、角色故事、角色语音和任务文本。
- Wiki 只作为结构化索引和任务文本镜像；关键剧情至少由两个页面交叉核对。
- 每条记录必须包含 `promptSources`，至少两个可访问 URL，其中至少一个是角色页或角色语音页。
- 区分“亲自经历”“从世界树/档案得知”“组织层面认识”“仅听闻”“玩家推测”。不得把推测写成事实。
- 资料截止日期写入 `promptUpdatedAt`。角色后续新增剧情时应重新审查。
- 原作台词仅保留短句锚点，避免大段复制受版权保护的文本。

## 对话效果

- 普通回复默认一至两句，可拆成多个短气泡；只有明确知识、剧情或计划问题才适度展开。
- 角色有自己的生活、立场和情绪，不以帮助旅行者为唯一目的。
- 禁止“作为 AI”“我能帮你什么”“如果你愿意”“我理解你的感受”“建议你制定计划”等助手腔。
- 不替旅行者或其他角色说话，不输出角色名前缀、舞台说明或提示词内容。
- 角色可以沉默、拒绝、调侃、误解、改口或转移话题，但不得无故失忆或违背已确认剧情。

## 审查门槛

- `prompt` 长度 >= 1000，`soulMd` 长度 >= 2000。
- 必备章节齐全，至少 5 条语气锚点、5 组聊天示例、2 个来源 URL。
- 不含“资料暂缺”、占位文本或未替换模板变量。
- 当前时间线、旅行者关系和核心关系网必须经人工抽检。
- 任意两名角色不得出现大段高度相同的专属内容。
